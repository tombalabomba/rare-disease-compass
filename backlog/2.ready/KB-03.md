# KB-03 — Fallakten-Ordner-Validierung

## Why
Claude Code liest den Fall-Ordner **direkt** als Dateien — es gibt keine
RAG-Ingestion und keinen Server mehr (Architektur-Pivot, `AGENTS.md` 2026-06-04,
`docs/architektur.md`). Damit der Ordner für den Assistenten zuverlässig nutzbar ist,
muss er der Konvention folgen: Pflichtsektionen vorhanden, HPO-IDs korrekt formatiert,
keine PII-Lecks. KB-03 liefert ein Validierungs-Skript, das genau das prüft und einen
klaren Report ausgibt — die maschinelle Absicherung der Ordner-Konvention aus SET-01.
Es **ersetzt** die früher geplante RAG-/Server-Ingestion: kein Index, keine DB, nur
eine lokale Prüfung des Markdown-Ordners.

## Scope
Skript + Tests + synthetische Ordner-Fixtures + Bedien-Doku:

**1. `tools/validate_case_folder.py`** (Python 3.11, `ruff`-clean, Stdlib + Import von
`tools/pii_guard.py`):
- **Eingang:** ein Pfad zu einem Fall-Ordner. Sucht darin die Fallakten-Datei(en)
  (`case-file*.md`).
- **Pflichtsektions-Prüfung:** verifiziert, dass die Akte die Pflichtsektionen aus
  dem KB-01-Template enthält (`## Stammdaten`, `## Zeitleiste`, `## Symptome`,
  `## Befunde`, `## Ausgeschlossenes`, `## Genetik-Zusammenfassung`,
  `## Offene Fragen`, `## Medikation`). Fehlende Sektionen → Befund.
- **HPO-Format-Validierung:** alle in der Symptom-Tabelle referenzierten HPO-IDs
  müssen dem Muster `HP:` + genau 7 Ziffern (`HP:[0-9]{7}`) entsprechen. Falsch
  formatierte IDs (z. B. `HP:123`, `HPO:0001250`, `HP0001250`) → Befund.
- **PII-Prüfung:** ruft `pii_guard.scan_file` (aus KB-02) auf jede Akten-Datei auf
  und meldet gefundene Lecks im Report.
- **Report + Exit-Code:** sammelt alle Befunde (fehlende Sektion / HPO-Format / PII)
  in einer Funktion `validate_case_folder(path) -> list[Issue]` und gibt einen
  lesbaren Report aus; CLI endet mit Exit ≠ 0, wenn Befunde existieren, sonst `0`.
- **CLI:** `python tools/validate_case_folder.py <ordner-pfad>`.

**2. `tools/tests/test_validate_case_folder.py`** (`pytest`): testet gegen
synthetische Ordner-Fixtures — gültiger Ordner ⇒ keine Befunde; Ordner mit fehlender
Sektion ⇒ Befund; Ordner mit falsch formatierter HPO-ID ⇒ Befund; und ein Test, der
beweist, dass `pii_guard` aufgerufen wird (PII in der Akte ⇒ PII-Befund im Report).

**3. Synthetische Ordner-Fixtures** unter `tools/tests/fixtures/`:
- `case-folder-ok/case-file-FIXTURE.md` — valide, vollständige, saubere Mini-Akte.
- `case-folder-missing-section/case-file-FIXTURE.md` — vollständige Akte minus einer
  Pflichtsektion.
- `case-folder-bad-hpo/case-file-FIXTURE.md` — sonst valide, aber mit einer falsch
  formatierten HPO-ID.
Alle erfunden, kein realer Mensch, kein `DD.MM.YYYY`.

**4. `docs/case-folder.md`** (deutsch): Bedien-Doku — was die Ordner-Konvention ist
(Verweis auf SET-01 `docs/project-layout.md` und KB-01-Template), wie man
`validate_case_folder.py` aufruft, was die Befunde bedeuten, und der klare Hinweis,
dass Claude Code den Ordner **direkt** liest (keine Ingestion/kein Server/keine DB).

## Out of scope
- **RAG/Ingestion/Vektor-Index/Server:** bewusst **entfernt** — KB-03 ersetzt das.
  Es wird kein Index gebaut, keine DB befüllt. Claude Code liest die Dateien direkt.
- **HPO-Existenz-Lookup gegen Live-DB:** KB-03 prüft nur das **Format** (`HP:`+7
  Ziffern), nicht ob die ID im HPO-Vokabular existiert (das ist `cli`-Epic).
- **PII-Detektor-Logik:** lebt in KB-02 (`tools/pii_guard.py`). KB-03 ruft nur auf.
- **Auto-Korrektur:** KB-03 meldet, repariert nicht.

## Notes
- **Single source of truth für Pflichtsektionen** ist das KB-01-Template. Die
  Sektionsliste hier daraus ableiten (gleiche Strings), nicht neu erfinden.
- **`pii_guard` als Import, nicht als Subprozess** — saubere Funktionsnutzung
  (`from pii_guard import scan_file` bzw. relativer Import je nach Paketstruktur).
  Keine doppelte PII-Logik in KB-03 (single source of truth = KB-02).
- **Kein Server, kein Netzwerk.** KB-03 ist reine lokale Datei-/Ordner-Prüfung —
  das ist der Architektur-Kern nach dem Pivot. `docs/case-folder.md` muss das
  explizit sagen, damit niemand wieder eine Ingestion erwartet.
