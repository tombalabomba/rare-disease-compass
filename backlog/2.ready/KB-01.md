# KB-01 — Fallakten-Schema/Template (HPO-codiert)

## Why
Die Fallakte ist das Herz des Systems: die pseudonymisierte, HPO-codierte
Krankengeschichte, die Claude Code als Dateien liest. HPO-IDs (Format `HP:0000000`)
sind der **Verbindungsschlüssel** zu den öffentlichen Datenbanken (PubCaseFinder,
Phen2Gene, Monarch) — ohne ein festes Schema codiert niemand die Symptome einheitlich
und die CLIs bekommen keinen sauberen Input. KB-01 definiert das verbindliche
Markdown-Template plus eine **synthetische** Beispiel-Akte. Es ist die Grundlage für
KB-02 (PII-Guard prüft Akten), KB-03 (Ordner-Validierung) und GEN-03 (füllt die
Sektion `## Genetik-Zusammenfassung`).

## Scope
Zwei neue Dateien — Template + synthetische Fixture:

**1. `docs/case-file-TEMPLATE.md`** — leeres, kommentiertes Template (deutsch) mit
diesen Pflichtsektionen (exakte Markdown-Überschriften, damit Acceptance per `grep`
und KB-03/GEN-03 darauf matchen):
- **`## Stammdaten`** — pseudonymisiert: Initialen (z. B. `M. M.`), Alter (Jahre,
  nicht Geburtsdatum), Geschlecht. Erklärender Kommentar: **kein** Klarname, **kein**
  exaktes Geburtsdatum (`docs/security.md`).
- **`## Zeitleiste`** — chronologischer Verlauf (Verlauf/Krankengeschichte).
- **`## Symptome`** — als **HPO-Tabelle** mit den Spalten `Symptom | HPO-ID | seit
  wann`. Mindestens eine erklärende Beispielzeile mit gültigem HPO-Format
  (`HP:0000000`).
- **`## Befunde`** — Endoskopie / Histologie / Labor (Untergliederung als Bullet-Liste
  oder Unterüberschriften).
- **`## Ausgeschlossenes`** — bereits ausgeschlossene Diagnosen/Differentialdiagnosen.
- **`## Genetik-Zusammenfassung`** — die Sektion, die GEN-03 später automatisch füllt.
  Im Template als Platzhalter mit Hinweis „wird von `rdc`/GEN-03 aus dem
  Exomiser-Ergebnis erzeugt". **Exakte** Überschrift, da GEN-03 denselben String
  produziert.
- **`## Offene Fragen`** — offene Fragen / Hypothesen.
- **`## Medikation`** — Medikation / Therapie-Verlauf.

**2. `docs/fixtures/case-file-FIXTURE.md`** — eine **synthetische** Beispiel-Akte
(ein **erfundenes** Kind), die dem Template exakt folgt: alle Pflichtsektionen
befüllt, plausible erfundene HPO-Symptome (gültiges `HP:0000000`-Format), erfundene
Befunde. **Keine** realen Namen, **kein** Geburtsdatum (`DD.MM.YYYY`), nur Initialen
+ Alter. Dient als Test-Fixture für KB-02/KB-03 und als Anschauungsbeispiel.

## Files
```
docs/case-file-TEMPLATE.md       (NEU)
docs/fixtures/case-file-FIXTURE.md (NEU, synthetisch — erfundenes Kind)
```

## Reality Check (Pflicht — vor Promotion nach `2.ready/`)
- [x] **Files in `Scope`/`Files`**: beide NEU. `docs/` existiert; `docs/fixtures/`
      wird neu angelegt.
- [x] **`depends_on`-IDs**: keine. KB-01 ist die Wurzel des knowledge-Epics; KB-02,
      KB-03, GEN-03 hängen von KB-01 ab, nicht umgekehrt.
- [x] **Externe Voraussetzungen**: keine. Reine Markdown-Dateien, kein Tool, kein
      Account.
- [x] **`.gitignore`-Allowlist verifiziert — ACHTUNG, BLOCKER-RISIKO:** Die
      `.gitignore` sperrt `**/case-file*.md` (Zeile 18) und will Template + Fixtures
      per Negation wieder freigeben (Zeilen 19–20). **Diese Negationen greifen
      aktuell NICHT**, weil sie einen **inline-Kommentar** am Zeilenende tragen — Git
      behandelt den Kommentar als Teil des Patterns, das Pattern matcht dann nie.
      Verifiziert:
      `git add docs/fixtures/case-file-FIXTURE.md` → „The following paths are ignored".
      Nach Entfernen des Trailing-Kommentars von Zeile 20 (Kommentar in eine eigene
      Zeile darüber verschieben) ist die Fixture trackbar (verifiziert in
      `/tmp`-Reproduktion: `git add` staged dann als `A`).
      `docs/case-file-TEMPLATE.md` ist betroffen (Zeile 19, gleicher Kommentar-Bug).
      → **Drive-by-Fix erlaubt (≤ 3 Zeilen, klar verstanden):** in der Implementierung
      die Trailing-Kommentare von `.gitignore` Zeile 19 + 20 in eigene Zeilen
      darüber verschieben, damit die Allowlist greift. Im Commit-Body als
      „Drive-by fix: .gitignore-Allowlist-Kommentare in eigene Zeilen" vermerken.
      Ohne diesen Fix sind Template + Fixture nicht committbar → die letzten zwei
      Acceptance-Checks würden fehlschlagen.
- [x] **Tooling**: nur `grep` + `git check-ignore` für die Acceptance. Beide
      verfügbar.

      Allowlist greift (ggf. nach Drive-by-Fix der `.gitignore`-Kommentare):

## Out of scope
- **PII-Prüf-Skript:** das automatische Aufspüren von PII-Lecks ist KB-02
  (`tools/pii_guard.py`).
- **Ordner-Validierung:** das Prüfen eines ganzen Fall-Ordners gegen die Konvention
  ist KB-03 (`tools/validate_case_folder.py`).
- **Füllen der Genetik-Sektion:** GEN-03 erzeugt den Inhalt von
  `## Genetik-Zusammenfassung`. KB-01 legt nur den leeren Platzhalter an.
- **HPO-Vokabular/Lookup:** das Nachschlagen, ob eine HPO-ID existiert/zum Symptom
  passt, ist Sache der CLIs (`cli`-Epic), nicht des Templates.

## Notes
- **Single source of truth für Sektions-Überschriften.** KB-03 (`grep` auf
  Pflichtsektionen) und GEN-03 (`## Genetik-Zusammenfassung` exakt) matchen gegen
  dieses Template. Überschriften hier festlegen und **nicht** später umbenennen,
  sonst brechen die abhängigen Tickets.
- **`## Genetik-Zusammenfassung` exakt so schreiben** — GEN-03 produziert denselben
  String, um die Sektion an der richtigen Stelle einzusetzen.
- **Fixture ist ein erfundenes Kind.** Initialen frei wählen (z. B. `M. M.`), Alter
  in Jahren, Geschlecht. Niemals ein reales Geburtsdatum, niemals einen realen Namen.
  HPO-IDs dürfen real existierende Codes sein (HPO ist öffentlich) — die **Person**
  ist erfunden.
- **`.gitignore`-Kommentar-Bug:** siehe Reality Check. Inline-Kommentare auf
  Negations-Zeilen brechen die Negation. Vor dem Anlegen der Dateien die `.gitignore`
  Zeilen 19–20 fixen (Kommentar in eigene Zeile), sonst lassen sich Template und
  Fixture nicht stagen. Drive-by-Fix im Commit-Body vermerken.
